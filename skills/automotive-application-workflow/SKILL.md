# 申請與流程協助 Skill

使用時機：使用者想用自然語言完成auto-repair的查詢、預約、整理或管理流程。

拆分理由：清單、準備資料、建立或更新流程需要明確邊界、確認與交付證據。

常見問法：

- 下一步
- 準備資料
- 幫我建立
- 幫我安排
- 如何送出

核心規則：

- 資料不足時要說明缺口，不得捏造結果或可用名額。
- 寫入、取消、付款前確認身份、輸入與影響範圍。
- 不要求使用者在聊天中提供密碼、OTP、token 或付款機密。
- 本地測試、部署、OAuth、付款與 ChatGPT 原生驗證分層回報。
- `/health` 對監控回傳 UTF-8 JSON；一般瀏覽器開啟同一網址時顯示可閱讀的健康頁，不公開內部診斷。

主要工具：

- `schedule_operation`：確認資源、時間與影響範圍後建立排程。
- `subscribe_alerts`：確認通知對象與管道後建立異常通知。
- `create_booking`：重新檢查名額與輸入並確認後建立預約。
- `approve_task`：核准任務：依輸入、前置條件與成功條件執行，不以產業名稱代替需求判斷。
- `send_notification`：發送通知：依輸入、前置條件與成功條件執行，不以產業名稱代替需求判斷。
- `assign_technician`：指派技師：依輸入、前置條件與成功條件執行，不以產業名稱代替需求判斷。
- `record_parts_usage`：零件使用紀錄：依輸入、前置條件與成功條件執行，不以產業名稱代替需求判斷。
- `book_notification`：book notification：依輸入、前置條件與成功條件執行，不以產業名稱代替需求判斷。
- `cancel_notification`：取消通知：依輸入、前置條件與成功條件執行，不以產業名稱代替需求判斷。
- `retry_notification`：重送通知：依輸入、前置條件與成功條件執行，不以產業名稱代替需求判斷。
- `schedule_job`：排程工作：依輸入、前置條件與成功條件執行，不以產業名稱代替需求判斷。
- `schedule_reminder`：排程提醒：依輸入、前置條件與成功條件執行，不以產業名稱代替需求判斷。
