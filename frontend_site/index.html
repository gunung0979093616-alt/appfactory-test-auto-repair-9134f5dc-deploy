Automotive Operations App

先找出塞車點，
再決定要改什麼。

整合三間維修廠的接車、工單、工位、技師技能、零件等待、報價核准、進度通知與交車。系統不會只看到加班就武斷判定是排班問題。

目前為隔離測試 App：通知只建立測試紀錄，不冒充簡訊或 LINE 已送達；Google 登入與正式供應商服務仍需專案擁有者授權。

診斷

流程瓶頸不是靠猜

依各節點等待分鐘數與未結案件數排序可能根因，要求補齊真實事件時間後才能凍結方案。

現場

工位與技能配對

工位占用會拒絕重複指派；技師配對先提供候選，不會在未確認前直接改派。

客戶

報價與通知留證據

報價維持待核准狀態；測試通知清楚標示未對外送達，避免把沙盒結果說成正式完成。

零件

待料影響透明化

保存品項、預估到貨與交期影響，讓主管知道延遲是供應鏈、工位或人力造成。

安全

寫入需要確認與冪等鍵

建立或更新動作必須明確確認且帶唯一操作碼，避免重複建立工單與通知。

交付

GitHub、Render、MCP 同版本

正式網址顯示的版本需與 GitHub commit、Render 部署及遠端工具清單一致。
